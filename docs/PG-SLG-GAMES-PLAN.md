# Playgrounds 短局 SLG 遊戲群計劃

> **狀態：** Proposed（2026-08-16）
> **權威約束：** 從屬 [PG-GAMES.md](./PG-GAMES.md)；純 HTML＋CSS＋JavaScript、無 build、mobile-first、可執行邏輯採 TDD
> **相關：** [playgrounds-host-api.md](./playgrounds-host-api.md)（`/api/kv`）、[`game-assets/ATTRIBUTION.md`](../game-assets/ATTRIBUTION.md)、既有 `pg-sandrts`／`pg-tinyfarm`／`pg-inkskirmish`／`pg-twland`
> **程式庫：** 每款各自建立 `sampot/pg-*` public repo；本地 `~/dev/sampot/pg-*`

一句話：用 **5～20 分鐘可完結、觸控優先、單一勝利條件** 的十款小品，補齊 Playgrounds 目前缺少的回合策略、資源調度與輕量 4X。

## 1. 遊戲群定案

| 批次 | id | 標題 | SLG 切片 | 目標局長 | MVP 勝利條件 |
| --- | --- | --- | --- | --- | --- |
| A1 | `pg-nightstall` | 夜市攤位爭霸 | 短局經營 | 8～12 分 | 12 夜後淨資產最高 |
| A2 | `pg-junzheng` | 三國一郡 | 回合領土 | 12～20 分 | 攻下敵城或守滿 12 回合 |
| A3 | `pg-alleyclaim` | 巷弄地盤 | 區域控制 | 8～12 分 | 8 回合後控制分最高 |
| B1 | `pg-pondfarm` | 塭仔養魚 | 風險經營 | 8～12 分 | 一造結束達成淨利目標 |
| B2 | `pg-pilgrim` | 廟會遶境路線 | 路線規劃 | 6～10 分 | 時限內回廟且香火達標 |
| B3 | `pg-lixuan` | 里長選舉 | 影響力配置 | 10～15 分 | 開票得票率最高 |
| C1 | `pg-railslot` | 高鐵時刻表戰 | 交通調度 | 6～10 分 | 尖峰結束達成準點與載客門檻 |
| C2 | `pg-pierbox` | 港口貨櫃 | 產能調度 | 8～12 分 | 班次結束合約分達標 |
| C3 | `pg-islesupply` | 島鏈補給 | 網路／後勤 | 10～15 分 | 連續 10 回合維持各島供應 |
| D1 | `pg-clubbudg` | 校園社團爭預算 | 資源配置 | 8～12 分 | 期末評鑑排名第一 |

### 1.1 系列

- 十款型錄均使用新系列 **`策略`**，避免把同一遊戲群分散到「街機／懷舊／桌遊」。
- 第一款進型錄時，才在 `catalog/series.yaml` 的 `game` 尾端新增 `策略`；規劃階段不先建立空系列。
- `PG-GAMES.md` 增設「打算實作」表，順序即本表批次順序。

### 1.2 共通產品邊界（硬）

- 每局有明確終點；不做永久城市、離線收成、每日登入、抽卡角色或課金加速。
- MVP 均為單人對 AI／系統壓力；Invite 只列 Phase 4+，不作上架門檻。
- 手機主操作限於點格、點卡、選指令與短拖曳；不得要求框選大量單位或 hover。
- 主畫面不得水平捲動；主 CTA 與目前回合／資源在窄屏首屏可見；觸控目標約 ≥44×44px。
- 禁止 `alert`／`confirm`／`prompt`。重開進行中局、清除紀錄才使用頁內確認；開始下一局不多問一次。
- 規則採可注入 seed 的 PRNG；相同 seed＋命令序列必須產生相同結果，方便測試與重播。
- 長期資料只存解鎖、最佳分數與設定，權威走 `/api/kv`；進行中局預設不跨裝置續玩。

## 2. 共通技術骨架

每款 repo 以同一骨架起步，但不抽成 runtime 共用依賴：

```text
pg-<id>/
  index.html
  app.js
  styles.css
  game/
    state.js       # 初始狀態、序列化
    rules.js       # 合法指令、回合推進、勝負
    events.js      # seed PRNG 與事件
    ai.js          # AI／自動調度
    scoring.js
    persist.js     # /api/kv；記憶體降級
  assets/
  ATTRIBUTION.md
  README.md
  game/*.test.js
  vitest.config.js
```

### 2.1 共通狀態契約

- `createGame({ seed, difficulty })` 建立純資料狀態。
- `getLegalActions(state)` 只回傳當前合法命令。
- `applyAction(state, action)` 回傳新狀態，不直接碰 DOM／計時器／網路。
- `advanceSystem(state)` 處理 AI、產出、事件與回合結算。
- `getOutcome(state)` 回傳進行中／勝／敗及可顯示原因。
- 動畫只呈現已完成的狀態轉移，不反過來承載規則。

### 2.2 共通畫面

| 面 | 職責 | 窄屏主 CTA |
| --- | --- | --- |
| 大廳 | 一句規則、難度、最佳紀錄 | 開始 |
| 局內 HUD | 回合／時間、2～4 個核心資源、目前目標 | 結束回合／執行 |
| 地圖／工作區 | 格子、路網、排程或卡片 | 依選取顯示可做動作 |
| 事件面 | 一次一個抉擇；不遮住必要資源資訊 | 選項 A／B |
| 結算 | 勝負原因、分數拆解、最佳紀錄 | 再玩一局 |
| 說明／關於 | 規則速查、設定、素材署名 | 返回 |

### 2.3 共通測試

- 每款都先測：初始資源、合法／非法指令、回合順序、產出與扣除、事件 seed 重現、勝負邊界、計分。
- AI 測試只要求動作合法、在固定 seed 下可結束，不承諾最優。
- `persist` 測試 KV 成功、404／失敗降級、壞 JSON 復原；不以裸 `localStorage` 當權威。
- UI 人工驗收至少覆蓋 360×800、觸控操作、鍵盤焦點、`prefers-reduced-motion`。

## 3. A1 夜市攤位爭霸（`pg-nightstall`）

### 玩法定案

- 4×3 攤位地圖，玩家與 2 名 AI 各經營一攤；共 12 夜。
- 每日下午依序：**進貨 → 定價 → 宣傳／備雨 → 開市結算**。
- 客流由入口、舞台、廁所與相鄰攤種影響；同類相鄰互搶，不同類形成「逛街組合」加成。
- 商品三類：小吃（穩定）、飲料（天熱強）、遊戲（毛利高但波動）。
- 事件只改當夜條件：下雨、演唱、臨檢、團客；不做永久卡組。
- 資源：現金、庫存、人氣；滯銷品隔夜折損。第 12 夜以現金＋剩餘庫存折價＋人氣獎勵計淨資產。

### AI、UI 與差異

- AI 性格：保守定價、低價搶客、高宣傳三種；根據預報與上夜銷量調整。
- 窄屏先顯攤位地圖與「進貨／定價／宣傳」底部操作盤；競品細節收進點選面板。
- ≠ `pg-tinyfarm`：不是格上等待作物成熟，而是需求預測、價格與空間競爭。
- ≠ `pg-twland`：沒有擲骰、買地與淘汰。

### 必測與資源

- 需求分配總人數守恆；同類競爭／互補加成；庫存不為負；雨天與備雨；12 夜結算平手規則。
- 美術優先自繪 CSS／SVG 攤棚＋`art/food-kit/`、`art/roguelike-modern-city/`；UI／音效用 Kenney UI packs。
- KV：`nightstall:best`、`nightstall:unlocks`、`nightstall:settings`。

## 4. A2 三國一郡（`pg-junzheng`）

### 玩法定案

- 單張 7 城節點圖；玩家控制 3 城，敵軍控制 3 城，中立關口 1 座。
- 每回合 3 枚政令，分配給 **屯田、徵兵、築城、移軍、出征、偵察**。
- 資源只有糧、兵、民心；三名將領只有武／智兩值與一個特性，避免角色養成膨脹。
- 軍隊移動消耗糧；斷糧先降士氣再逃兵。戰鬥以兵力、士氣、城防、將領與小幅 seed 波動一次結算。
- 玩家可選「攻城」劇本（12 回合內取敵都）或「守郡」劇本（守滿 12 回合）。

### AI、UI 與差異

- AI 先確保糧線，再評估鄰城攻守比；困難模式會佯攻薄弱城。
- 地圖採節點而非自由格；點城後只顯合法政令，回合結束一次演出雙方命令。
- ≠ `pg-sandrts`：純回合政令與補給，沒有即時建造、單位微操或空襲。
- ≠ `pg-junqi`／`pg-xiangqi`：不是棋子吃子規則。

### 必測與資源

- 政令上限、移軍鄰接、糧耗、補給線、攻城／撤退、同時命令順序、雙勝條件優先級。
- 軍事圖示可用 `art/rts/` 統一調色後的建築／單位；人物以自繪章牌，避免混搭畫風。
- KV：`junzheng:best`、`junzheng:unlocks`、`junzheng:settings`。

## 5. A3 巷弄地盤（`pg-alleyclaim`）

### 玩法定案

- 5×5 街廓，含市場、廟口、公園、派出所四個地標；玩家與 2 AI 各有 6 枚影響力。
- 共 8 回合，每回合秘密選一枚棋與目標格，再同時揭示。
- 空格直接進駐；衝突比較投入＋相鄰支援；敗方退回，不永久消滅。
- 地標每回合產分：市場 2、廟口 2、公園 1、派出所 1；連成三格路線另得 2 分。
- 每位玩家每局一次「里民大會」，讓某格本回合支援加倍。

### AI、UI 與差異

- AI 評估地標、連線、封阻與衝突風險；固定 seed 可重播秘密命令。
- 手機先點己方棋，再高亮合法格；揭示前可撤回，不用原生確認。
- ≠ `pg-inkskirmish`：回合同時下令、離散控制分，不是即時移動塗色。
- ≠ `pg-twland`：沒有經濟、骰子或資產淘汰。

### 必測與資源

- 移動鄰接、同時衝突、三方平手、支援計算、地標與連線重複計分、8 回合結算。
- 美術以 CSS 街廓＋`art/roguelike-modern-city/` 圖示；棋子可用 `art/boardgame-pack/`。
- KV：`alleyclaim:best`、`alleyclaim:settings`。

## 6. B1 塭仔養魚（`pg-pondfarm`）

### 玩法定案

- 6 格魚塭跑一造 10 週；可放虱目魚、白蝦或混養。
- 每週先看天氣預報，再分配 3 點工：放苗、餵料、換水、增氧、檢測、收成。
- 核心狀態為存量、平均重量、水質、溶氧、病害；密度越高成長快、缺氧與病害風險也越高。
- 颱風不是純隨機懲罰：預報後可提前收成或加固；過晚收成則價格與風險拉扯。
- 第 10 週或提前清塘，以銷售額－苗／飼料／設備成本計淨利。

### 差異、測試與資源

- ≠ `pg-tinyfarm`：重點是密度、水質、混養與提前收成風險，不是作物成長格。
- 必測成長、載量、溶氧、病害機率 seed、混養加成、提前／期末收成與死亡上限。
- 魚可用 `art/fish-pack/`；塭格與設備以 CSS／SVG；KV：`pondfarm:best`、`pondfarm:unlocks`。

## 7. B2 廟會遶境路線（`pg-pilgrim`）

### 玩法定案

- 12 節點街區，從主廟出發並在 18 時段內回廟；必訪 3 個指定宮壇。
- 每段路消耗時間與體力；店家、宮壇、補給點提供香火、體力或捷徑。
- 每回合可移動、休息或使用一次性協調令；道路事件含塞車、陣頭交會、午後雷雨。
- 「擾民」值會因重複走住宅區與夜間鼓陣上升，過高扣香火；最短路不一定最好。
- 回廟且必訪完成才有資格計分：香火＋剩餘體力－超時／擾民。

### 差異、測試與資源

- ≠ `pg-deliver`：不是即時駕駛；是時間窗、必訪點與風險路線規劃。
- 必測路徑鄰接、時間窗、必訪集合、事件封路、超時、回廟資格與計分。
- 文化符號採抽象自繪，不挪用特定廟宇商標；UI 可用 board-game icons；KV：`pilgrim:best`、`pilgrim:routes`。

## 8. B3 里長選舉（`pg-lixuan`）

### 玩法定案

- 6 個鄰里、4 週、玩家對 2 AI；每週分配 4 點行動。
- 行動：拜訪、辦活動、提政見、處理陳情、澄清；資源為志工、經費、信任。
- 各鄰里關心交通、治安、環境或長照；對應政見才有效，過度承諾會增加可信度風險。
- 民調只顯區間，不揭露精確票數；最後一週可催票但不能憑空逆轉低信任。
- 不提供抹黑按鈕；負面事件以「謠言／爭議是否回應」呈現，維持輕鬆社區治理題材。

### 差異、測試與資源

- ≠ 純選舉數值模擬：重點是議題匹配、有限資訊與地區配置。
- 必測行動點、議題匹配、信任上下界、民調誤差 seed、AI 合法性、開票與平手。
- 以 CSS 社區地圖、`art/emotes-pack/`／`art/board-game-icons/` 表情圖示；KV：`lixuan:best`、`lixuan:settings`。

## 9. C1 高鐵時刻表戰（`pg-railslot`）

### 玩法定案

- 簡化為 6 站單線走廊、上下行各 4 班；一局是 120 分鐘尖峰。
- 玩家排發車槽、停靠模式與待避；每班有載客需求、轉乘承諾與最低折返時間。
- 模擬以 5 分鐘 tick 推進；同區間安全間隔不足即禁止排程，不靠玩家反應補救。
- 隨機事件只有延誤分鐘數；玩家可跳停、延後或換月台，承擔乘客與準點損失。
- 結算同時計算準點率、載客量與取消數；三項門檻皆過才勝。

### 差異、測試與資源

- ≠ `pg-deliver`：是排程約束求解，不是路上閃避。
- 必測區間占用、安全間隔、停靠時間、折返、延誤傳播、跳停乘客轉移與三門檻。
- 車站／列車以自繪 SVG 與 road textures 改作線路；不得使用高鐵公司商標或真實塗裝。KV：`railslot:best`。

## 10. C2 港口貨櫃（`pg-pierbox`）

### 玩法定案

- 6×4 堆場、2 台岸橋、1 台場橋；一班 10 輪。
- 貨櫃有船次、重量級與截止輪；只能從堆疊頂端移動，危險品需隔離。
- 每輪新增進港櫃並給 3 點設備工時；玩家決定卸船、翻櫃、裝船或暫存。
- 提前按船次分區可少翻櫃，但會犧牲空間；逾期與錯船重罰。
- 結算為準時合約分－翻櫃成本－逾期罰分；堆場無合法位置立即敗。

### 差異、測試與資源

- ≠ `pg-carjam`：不是固定盤面滑塊解謎，而是持續到貨、設備瓶頸與截止時間。
- 必測堆疊頂限制、重量／危險品、工時、船次截止、無位置敗局、翻櫃成本。
- 貨櫃與吊車採 CSS／SVG 統一幾何風；`factory-kit` 僅作參考或預覽素材。KV：`pierbox:best`、`pierbox:unlocks`。

## 11. C3 島鏈補給（`pg-islesupply`）

### 玩法定案

- 7 島節點圖、3 艘船；各島每回合消耗糧、藥、燃料中的 1～2 種。
- 主島生產，外島有倉儲上限與少量特產；船受載重、航程與風向影響。
- 玩家排每艘船下一段航程與裝卸；命令同時執行，抵達後才可用貨。
- 預報顯示未來兩回合風向／颱風機率；可繞路、預屯或停航。
- 任一有人島缺關鍵物資連續 2 回合即敗；維持全島 10 回合即勝。

### 差異、測試與資源

- ≠ `pg-seabattle`：沒有猜船與開火；全部深度在庫存、載重、時序與風險。
- 必測載重、裝卸順序、抵達時點、倉儲溢出、消耗優先級、連缺兩回合、風向航時。
- 地圖與船採自繪 SVG／board-game icons；KV：`islesupply:best`、`islesupply:unlocks`。

## 12. D1 校園社團爭預算（`pg-clubbudg`）

### 玩法定案

- 一學期 8 週，玩家經營一個社團並與 3 AI 爭取場地、社員與期末預算。
- 每週 3 點幹部工時，投入招生、練習、辦活動、寫企劃、維護器材。
- 場地透過同時密封申請：投入聲望與企劃品質，非金錢競標；落選仍可選次級場地。
- 社員有興趣而非個別角色養成；活動成功取決於準備、場地適配與當週事件。
- 期末評鑑依參與、成果、財務與安全四項加權；任何一項過低都會限制總評。

### 差異、測試與資源

- ≠ `pg-sealedbid`：密封申請只是每週一環，主體是整學期資源配置。
- 必測工時、場地衝突與平手、社員流動、活動成功 seed、四項評鑑門檻與 AI 合法性。
- 美術用 `art/emotes-pack/`、`art/game-icons/`、`art/medals/`；KV：`clubbudg:best`、`clubbudg:unlocks`。

## 13. 分批實作與驗收

### 13.1 批次順序

1. **A：核心三型** — `pg-nightstall`（經營）、`pg-junzheng`（領土）、`pg-alleyclaim`（區控）。
2. **B：台灣題材** — `pg-pondfarm`、`pg-pilgrim`、`pg-lixuan`。
3. **C：調度三部曲** — `pg-railslot`、`pg-pierbox`、`pg-islesupply`。
4. **D：非戰鬥收尾** — `pg-clubbudg`。

同批仍逐款完成，不同時開三個半成品；前一款通過 Phase 3 才開始下一款。

### 13.2 每款固定 Phase

| Phase | 內容 | 完成標準 |
| --- | --- | --- |
| **0** | 規則純函式＋失敗測試 | 核心狀態、合法命令、勝負與 seed 測試綠 |
| **1** | 最小可玩 DOM＋AI | 無美術也能從開局玩到結算；AI 可完局 |
| **2** | mobile-first UI、音效、教學 | 360×800 不水平捲動；主要操作可觸控完成 |
| **3** | KV、難度、署名、型錄 `unlisted` | 場殼與 go 可開；失敗降級可玩；ATTRIBUTION 完整 |
| **4** | 打磨後 `listed` | 人工手機驗收、規則文案與最佳紀錄正確 |
| **5+** | Invite／每日種子／額外劇本 | 非上架門檻 |

### 13.3 每款上架檢查

- [ ] 獨立 repo；無 `node_modules`、無 build、無 committed 套件依賴
- [ ] `npx vitest run` 綠；規則邏輯依 TDD 完成
- [ ] 360×800 與桌面皆可完局；無原生 dialog
- [ ] `/api/kv` 成功與失敗降級都驗過
- [ ] 素材複製進遊戲 repo；`ATTRIBUTION.md` 逐項列作者、pack、URL、授權
- [ ] `catalog/entries/pg-*.yaml`、`catalog:gen`、`PG-GAMES.md` 狀態同步
- [ ] GitHub `sampot/pg-*` public；go 與場殼可開
- [ ] 先 `unlisted`，打磨與人工驗收後再 `listed`

## 14. 風險與控制

| 風險 | 控制 |
| --- | --- |
| 十款規則看似不同但玩起來都在點數字 | 每款鎖一個獨特空間模型：攤位、節點城、街廓、魚塭、路線、選區、時刻表、堆場、航網、場地 |
| 規則與 UI 同時膨脹 | MVP 核心資源 ≤4、每回合主要動作 ≤6、單局事件種類約 8～12 |
| AI 開發拖慢 | 啟發式評分＋合法性優先；不做搜尋型完美 AI |
| 題材誤用真實機構／商標 | 高鐵、選舉、廟會皆採虛構名稱與抽象圖示 |
| 素材風格不一致 | 每款只選一套主視覺；缺圖以 CSS／SVG 補，不混用多套寫實度 |
| 手機資訊過載 | 地圖＋底部情境操作盤；詳細數值按需展開，不把全表常駐首屏 |
